# 提示词管理

多套命名系统提示词，卡片列表里点「应用」即切换，下一回合生效。分全局与项目两层。

## 用法

1. 设置 → 提示词管理。
2. 上方两个页签：**全局提示词** 对所有会话生效；**项目提示词** 只在工作目录落在该项目里的会话生效。
3. 每套提示词是一张卡片，点「应用」切过去，点「展开」看全文，点「编辑」改正文与名字。
4. 右上角「+ 添加全局提示词」新建；项目页签里从「选择已有工作区」下拉里挑一个（没有合适的就手填目录），点「+ 新建分组」，再在该分组里「+ 添加」。
5. 标题右边的勾选框是总开关：关掉后两层都不注入，库都留着。

## 项目提示词怎么归属

宿主在每次组装系统提示词时拿到当前会话的工作目录（`agent.session.header.cwd`），
与项目路径做前缀匹配：同目录或子目录都算命中，多层命中时取最长（最具体）的那个项目。
命中项目就用该项目的选中模板，没命中退回全局。

路径比较前会归一（反斜杠、末尾斜杠、大小写），`D:\code\site` 与 `d:/CODE/SITE` 是同一个项目。

## 注入位置

`systemPrompt.section({ order: 10300 })`，排在 DSH 自带段之后（部署人格后缀是 10200），也就是系统提示词最下面。
`complete: true` 会用正文取代整份系统提示词，工具说明也一起没了，只在明确知道后果时用。

## 库存在哪

插件配置里两个 JSON 字符串：

- `config.templates` — 全局库：`[{"name":"编码","text":"……"}]`
- `config.projects` — 项目库：`{"D:/code/site":{"templates":[…],"active":"前端"}}`
- `config.workspaces` — 见过的工作目录，JSON 数组、最新在前、最多 40 条。插件在每回合注入时顺手记下当前会话的 `cwd`，设置页拿它当「选择已有工作区」的下拉项。只是候选路径，删掉不影响已建的分组。

配置落在 profile 的 `cordis.patch.yml` 里条目 `prompt-manager` 下。设置页与工具写的是同一份数据。

## 也让 agent 切

`prompt_manager` 工具：`list` / `use` / `add` / `set` / `remove` / `on` / `off`，
以及项目版 `project-list` / `project-add` / `project-use` / `project-remove`（带 `path` 参数）。
直接说「切到写作模板」也行。

## 边界

- 与其它注入插件共用系统提示词时，两段都会进上下文；用同一段位置 (order) 靠先后顺序决定，不会互相覆盖。
- 改 `order` 或 `complete` 需要重挂插件条目，改正文、`active`、`projects` 不用。
- 设置页改动即时写入配置，没有保存按钮。
